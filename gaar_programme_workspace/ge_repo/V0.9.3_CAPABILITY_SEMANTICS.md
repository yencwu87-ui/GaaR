# v0.9.3 — Capability semantics / outcome determinism

## Changes

1. Canonical framework keys
   - Added one canonicalizer for MAS/MGF framework names.
   - `authoritative_decisions()` uses canonical keys.
   - Event write boundary canonicalizes MAS/MGF framework values so legacy values such as `MGF Agentic` are persisted as `MGF`.

2. Capability status semantics
   - `blocked` is now distinct from `contradicted`.
   - `escalate` is distinct from both `blocked` and `supported`.
   - `supported` requires all mapped governed items for that capability to be full.
   - Empty/insufficient capability coverage remains `insufficient`.

3. First-class global capability evaluation
   - Added `evaluate_capabilities_global()`.
   - Capabilities are evaluated once over the complete crosswalk and then selected by outcomes.
   - Repeated bindings for the same framework/control/element are deduplicated with deterministic evidence-mode union.

4. Outcome aggregation
   - Outcomes now derive posture primarily from required capability status.
   - Hard blockers still propagate to `defer`.
   - Required capability insufficiency produces `remediate`.

5. Deterministic, evidence-aware next actions
   - Actions are mechanically generated from governed element state.
   - Evidence modes are included in the action text.
   - Ordering is stable.

6. Safe YAML caching
   - Parsed YAML is cached by file mtime for performance.
   - Callers receive deep copies so a caller/test cannot mutate the cached object.

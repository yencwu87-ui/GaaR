# v0.6 Evidence-Lineage Architecture

```text
Reviewer Read
    |
    v
Claim Decomposition
    |
    v
Claim Register ----> Evidence Ledger
    |                     |
    |                     v
    +--------------> Grounding Gate
                          |
                    eligible claim
                          |
                          v
                      Challenger
                          |
                          v
                   Rebuttal Gate
                          |
                +---------+---------+
                |                   |
              strong            weak/rejected
                |                   |
                v                   v
          substantive          refine/request
```

## State rules

- `supported` claim: may be refined, but not strongly overturned by the same evidence.
- `contradicted` claim: eligible for a strong rebuttal if the rebuttal pointer is valid.
- `unsupported` claim: may trigger an evidence request; absence is not contradiction.
- `unclear` claim: request clarification/evidence.
- missing or unknown `claim_id`: rejected for reviewer-read challenge.
- claim-vetting transport/parse failure: fail closed; do not run the generic reviewer-read Challenger.

## Provenance

`challenge -> claim_id -> claim_fingerprint -> evidence_id -> factual_pointer -> requirement element`

The LLM proposes the argument; deterministic validation decides admissibility.

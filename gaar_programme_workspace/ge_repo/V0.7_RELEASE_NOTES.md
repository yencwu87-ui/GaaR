# v0.7 — Falsification Engine

v0.7 builds on v0.6 Evidence-Lineage Governance. The Challenger still cannot directly create a
substantive governance conclusion. Instead, the engine creates bounded falsification probes over
vetted claims.

## New invariants

1. Every falsification probe targets a registered `claim_id`.
2. The probe's `requirement_element_id` must match the claim's governed element.
3. Every cited `evidence_id` must exist in the engine-built Evidence Ledger.
4. Every probe is bound to an immutable Context Package containing claim/evidence/requirement IDs,
   source-version hashes, model and prompt version.
5. Unsupported claims are routed to evidence requests rather than fabricated counterfactuals.
6. Probe status and claim coverage are deterministic engine outputs; the LLM cannot promote a draft
   into an executable probe.

## Probe classes

- `counterfactual` — test the minimum condition under which the proposition would fail.
- `missing_condition` — expose necessary conditions, exceptions, or operating circumstances not established.
- `alternative_interpretation` — test whether the same evidence has a materially different governed reading.
- `evidence_request` — identify the artefact needed to establish or falsify an unsupported/unclear claim.

The MVP generates bounded probe hypotheses deterministically from the claim register and compiles them
through the same lineage gate. This keeps v0.7 auditable without introducing another probabilistic decision layer.

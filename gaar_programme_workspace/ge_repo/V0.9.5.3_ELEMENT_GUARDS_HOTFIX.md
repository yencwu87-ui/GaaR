# v0.9.5.3 — M3.6 element-integrity hotfix

This build addresses the 2026-09-14 M3.6 decomposition failure.

## What changed

- PDF running-header/page-number text is stripped before sentence enumeration.
- Model-generated requirement elements are gated for obligation shape and meaningful targets.
- Each element must retain material lexical provenance to its own source sentence.
- Explicit subject/actor swaps are rejected when the source identifies a different governed actor.
- Verified anchors are rejected if they are fragments, headers, or obvious footnote spill.
- Maximum three promoted elements per selected sentence; further outputs are retained as overflow diagnostics rather than silently promoted.
- Draft output separates sentence selection rate from element integrity and reports rejected/overflowed elements.
- M3.6 was revised to a seven-element, source-aligned contract, including the previously missing validation scope and effective-challenge requirements, while retaining pre-deployment, risk-materiality and re-validation requirements.
- M3.6 corpus labels were re-argued against the revised contract and rebound to requirement SHA `6a57b78f6b44`: `_a=partial`, `_b=partial`, `_c=none`.
- Local Ollama calls default to a 120s timeout, 16k context and 1200 output tokens; all are configurable via environment variables.

## Verification

Targeted regression suite: **52 passed**.

The repository-wide `eval/corpus_labels.py --check` still reports a pre-existing unrelated M3.12 corpus problem (`e0/e3b/e4` are not in its current requirement overlay). This build does not silently alter M3.12 to make the global check green.
